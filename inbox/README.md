# 📥 경영 메모 인박스

> 이동 중에 떠오른 한 줄을 텔레그램에 던지면, 봇이 받아서 노션 대장과 장부에 이중으로 쌓는다.

```
나:  도쿄 하라주쿠 매장 주말 오후 대기줄 30분 #브라운 #오프라인
봇:  📥 47번째 기록 저장! 📝 메모 #브라운 #오프라인
     노션에도 적어뒀어요 ✓
```

앱 안 열고, 폴더 안 정하고, 제목 안 짓는다. 던지면 쌓인다.
나중에 `/api/inbox?format=md` 로 통째로 꺼내면 그게 주율회의·경영 판단의 재료가 된다.

출처 — [jisun5/telegram-memo-inbox](https://github.com/jisun5/telegram-memo-inbox) 스킬(에듀파이 이지선)을
현장 관찰·경영 메모 용도로 재구성했다.

---

## 핵심 설계

**이 봇은 Claude를 거치지 않는다.** 웹훅이 직접 받아서 직접 저장한다.
그래서 새벽 3시에 던져도, PC가 꺼져 있어도, 세션이 끊겨 있어도 저장된다.
(Claude 세션을 경유하는 봇은 세션이 살아 있을 때만 동작한다 — 인박스로는 실격이다.)

```
텔레그램  ──►  /api/telegram  ──►  Vercel Blob 장부 (원본)
                              └──►  노션 DB       (미러)

회수      ──►  /api/inbox?format=md
```

**원본은 장부, 노션은 미러다.** 노션이 죽어도 기록은 남는다.

---

## 던지는 법

**아무 말이나 보내면 저장된다.** 아래는 전부 *써도 되고 안 써도 되는* 것들이다.

| | 쓰는 법 | 예 |
|---|---|---|
| **종류** | 접두어 + 콜론 | `관찰:` `이슈:` `아이디어:` `결정:` `숫자:` `구성원:` |
| **태그** | 해시태그 | `#브라운` `#BIZ1` `#오프라인` `#라이센스` `#에디슨마마` |
| **온도** | 첫 글자 이모지 | 🔥 급함 ⚠️ 위험 🤔 생각 👍 좋음 |

```
관찰: 하라주쿠 주말 오후 대기줄 30분 #브라운 #오프라인
🔥 이슈: BIZ2 라이센스 갱신 3주째 정체 #BIZ2 #라이센스
숫자: 9월 온라인 누적 4.2억엔, 전월비 +8% #온라인
구성원: 다나카 상 컨셉 리뷰 준비도가 올라왔다 #피플
그냥 떠오른 한 줄            ← 이것도 된다. 이게 기본이다.
```

> **접두어를 필수로 만들지 않은 것이 이 설계의 핵심이다.**
> 이동 중에 매번 `관찰:` 을 붙여야 하는 봇은 두 달 안에 죽는다.
> 접두어가 없으면 전부 「📝 메모」로 저장되고, 그걸로 충분하다.

명령 — `핑`(연결 확인 5초) · `/통계`(최근 7일 분포) · `/도움`

## 만드는 순서

### 1단계 — 봇 만들기 (대표님이 직접 하셔야 하는 부분)

텔레그램에서 **@BotFather** 를 찾아 대화 시작.

1. `/newbot`
2. 봇 이름(표시용, 한글 가능) → 예: `경영 메모 인박스`
3. 봇 아이디(영문, `_bot` 으로 끝나야 함) → 예: `lfj_memo_inbox_bot`
4. **토큰이 나온다.** `1234567890:AA...` 형태 → `BOT_TOKEN`

> ⚠️ **토큰은 비밀번호다.** 채팅창·저장소·발표자료에 남기지 않는다.
> 노출됐으면 BotFather `/revoke` 로 즉시 재발급.

5. 만든 봇 대화방에 들어가 **아무 말이나 한 번 보낸다** (이걸 해야 chat_id가 생긴다)
6. chat_id 확인 → `MY_CHAT_ID`

```bash
curl -s "https://api.telegram.org/bot<토큰>/getUpdates"
```

응답의 `message.chat.id` 숫자다.

> 💡 **웹훅을 등록한 뒤에는 `getUpdates` 가 동작하지 않는다.**
> 순서를 지킨다 — chat_id 먼저, 웹훅 나중.

### 2단계 — 노션 DB 만들기

1. 노션에서 **새 페이지 → 데이터베이스(표)** 생성
2. 속성을 **이름까지 정확히** 맞춘다:

| 속성 이름 | 유형 |
|---|---|
| `제목` | 제목 |
| `날짜` | 날짜 |
| `종류` | 선택 |
| `출처` | 선택 |
| `태그` | 다중 선택 |
| `온도` | 선택 |

3. [notion.so/my-integrations](https://www.notion.so/my-integrations) → **새 integration → 토큰 복사** → `NOTION_TOKEN`
4. **만든 DB 페이지에서 `⋯` → 연결 → 방금 만든 integration 추가**
   ← **이걸 빼먹으면 계속 404가 난다.** 가장 흔한 함정이다.
5. DB URL의 32자리가 `NOTION_DB`
   `notion.so/<워크스페이스>/<32자리>?v=...`

> 선택 값(`종류`·`출처`)은 봇이 보내면 자동 생성된다. 미리 만들어둘 필요 없다.

### 3단계 — 배포

이 폴더가 Vercel 프로젝트 루트다. (레포 루트에는 다른 앱이 있으니
Vercel 프로젝트 설정에서 **Root Directory 를 `inbox` 로** 지정한다.)

```bash
cd inbox
npx vercel --prod --yes
```

Vercel 프로젝트 설정 → Environment Variables 에 넣는다 (`.env.example` 참고).
**넣은 뒤 반드시 재배포해야 적용된다.**

| 이름 | 값 |
|---|---|
| `BOT_TOKEN` | BotFather 토큰 |
| `MY_CHAT_ID` | 내 chat_id |
| `TG_WEBHOOK_SECRET` | 아무 긴 임의 문자열 (직접 정함) |
| `NOTION_TOKEN` · `NOTION_DB` | 2단계에서 확보 |
| `INBOX_READ_KEY` | 회수 API 열쇠 (비우면 회수 API가 닫힌다) |
| `BLOB_BASE_URL` | *선택* — 아래 "장부 읽기 최적화" 참고 |

Vercel 프로젝트에 **Blob 스토어를 연결**한다 (Storage → Blob → Connect).
`BLOB_READ_WRITE_TOKEN` 은 이때 자동으로 주입된다.

### 4단계 — 웹훅 연결

**이 한 줄이 봇과 서버를 잇는다.**

```bash
curl -s "https://api.telegram.org/bot<토큰>/setWebhook?url=https://<내프로젝트>.vercel.app/api/telegram&secret_token=<TG_WEBHOOK_SECRET>"
```

`{"ok":true,"result":true}` 가 나와야 한다.

### 5단계 — 검증 (여기를 건너뛰지 않는다)

**"됐습니다" 라는 말로 끝내지 않는다. 세 개를 실제로 확인한다.**

1. 봇에게 **`핑`** → `퐁! 인박스 직통 연결 정상이에요 📥` ← 웹훅 연결 정상
2. 아무 한 줄 → `📥 1번째 기록 저장!` 회신 확인
3. **노션 DB를 열어 줄이 실제로 생겼는지 눈으로 확인** (회신에 `노션에도 적어뒀어요 ✓` 가 붙었는지)

안 되면 원인은 여기에 있다:

```bash
curl -s "https://api.telegram.org/bot<토큰>/getWebhookInfo"
```

| 증상 | 원인 |
|---|---|
| 아무 반응 없음 | 웹훅 미등록 / URL 오타 / 배포 안 됨 |
| 같은 메시지 무한 반복 | 200이 아닌 응답을 돌려주고 있음 |
| `unauthorized` | `setWebhook` 의 `secret_token` 과 `TG_WEBHOOK_SECRET` 불일치 |
| 저장은 되는데 노션만 빔 | **DB에 integration 연결 누락(2-4단계)** / 속성 이름 불일치 |
| 날짜가 하루 어긋남 | KST 보정 누락 (이 코드는 보정되어 있다) |

## 회수 — 인박스는 비워야 인박스다

쌓기만 하면 6개월 뒤 "뭔가 많이 쌓였는데 못 쓰겠다"가 된다. **회수 주기를 정한다.**

```bash
# 이번 달 전체를 마크다운 정리본으로
curl "https://<프로젝트>.vercel.app/api/inbox?key=<INBOX_READ_KEY>&from=2026-09-01&format=md"

# 특정 IP 건만
curl "https://<프로젝트>.vercel.app/api/inbox?key=<열쇠>&tag=브라운"

# 이슈만 모아 보기
curl "https://<프로젝트>.vercel.app/api/inbox?key=<열쇠>&kind=이슈&format=md"
```

필터 — `from` `to` `kind` `tag` `q`(본문 검색) `limit` `format=md`

**권장 주기**
- **주간** — `kind=이슈` 를 훑고 주율회의 안건으로 올릴 것만 고른다
- **월간** — `format=md` 통째로 꺼내 IP별·채널별로 묶는다
- **분기** — 태그 분포(`/통계`)를 보고 실제로 무엇을 관찰하고 있었는지 확인한다

## 이 코드가 지키는 것 (실전에서 데인 것들)

1. **웹훅은 항상 200을 반환한다.** 에러를 돌려주면 텔레그램이 같은 메시지를 끝없이 재전송한다.
2. **관문 두 개를 다 건다.** `secret_token` 헤더 + `chat_id` 화이트리스트. 봇 아이디는 공개라 누구나 말을 걸 수 있다.
3. **웹훅을 쓰는 봇에 `getUpdates` 를 호출하지 않는다.** 둘은 동시에 못 쓴다.
4. **미러 실패가 원본 저장을 막지 않는다.** 노션이 죽어도 글은 남는다.
5. **노션 select 라벨은 한글로.** 영문(`telegram`)이면 브라우저 번역기가 **"전보"** 로 오역해서 보여준다.
6. **서버 시간은 UTC다.** KST 보정 없이 날짜를 찍으면 밤에 쓴 글이 전날로 들어간다.
7. **토큰·chat_id는 절대 코드나 저장소에 넣지 않는다.** 전부 환경변수.
8. **Windows에서 한글을 `curl -d` 로 보내지 않는다.** 깨진다. UTF-8 파일로 `--data-binary @file` 하거나 python 으로.
9. **저장소 목록 조회(`list()`)를 쓰지 않는다.** Vercel Blob "고급 작업"은 무료 플랜 월 2,000회이고,
   넘기면 **계정의 저장소 전체가 차단된다**(다른 서비스까지 멈춘다). 이 코드는 `list()` 를 아예 부르지 않는다.
10. **회신에 번호를 넣는다.** `47번째 기록 저장!` — 쌓이는 감각이 이 봇의 수명을 결정한다.

### 원본 스킬에서 고친 것

- **장부 보호** — 원본은 장부 읽기가 실패해도 빈 배열을 돌려준 뒤 그대로 저장한다.
  그러면 **그동안 쌓은 기록 전체가 1건으로 덮어써진다.** 이 코드는 "장부 없음"과 "못 읽음"을
  구분하고, 못 읽었으면 저장을 중단하고 사용자에게 알린다.
  저장 한 번 실패는 회복되지만 장부가 날아가는 건 회복되지 않는다.
- **이모지 + 접두어 동시 인식** — 원본은 접두어를 먼저 찾아서 `🔥 이슈: ...` 가 전부
  「메모」로 떨어진다. 급한 걸 먼저 표시하는 게 사람의 실제 습관이라 분류가 통째로 죽는다.
  온도 → 접두어 → 온도 순으로 본다.
- **`list()` 제거** — `head()` 로 바꾸고, `BLOB_BASE_URL` 이 있으면 고급 작업 호출이 0회가 된다.
- **회수 API** — 원본은 "만들어 두면 좋다"고만 남겼다. 필터와 마크다운 출력까지 붙였다.

### 장부 읽기 최적화 (`BLOB_BASE_URL`)

`addRandomSuffix: false` 로 저장하므로 장부 URL이 결정적이다.
Blob 스토어의 공개 베이스 URL(`https://xxxxxxxx.public.blob.vercel-storage.com`)을
`BLOB_BASE_URL` 에 넣으면 **고급 작업 호출이 0회**가 된다 (계명 9).
넣지 않으면 서버 인스턴스당 `head()` 를 한 번 부른다 — 이것도 안전하지만, 넣는 쪽이 낫다.

## 알려진 한계

- **텍스트만 저장한다.** 사진·음성은 아직이다.
- **동시 저장 경합** — 같은 순간에 두 건을 던지면 장부는 읽고-고쳐-쓰기라 한 건이 밀릴 수 있다.
  혼자 쓰는 인박스에서는 사실상 일어나지 않지만, 구조적으로 존재하는 한계다. 노션 미러에는 둘 다 남는다.
- **장부가 한 파일이다.** 하루 10건이면 1년에 약 700KB — 문제없다. 그 이상이면 월별로 나눠야 한다.

## 시험

```bash
cd inbox && npm install && npm test
```

파서 27개 + 웹훅 통합 32개. 통합 시험은 텔레그램·노션·Blob 을 전부 가짜로 세워
**관문 두 개 · 항상 200 · 장부 보호 · 미러 실패 격리** 가 실제로 작동하는지 확인한다.
`test/blob-stub.mjs` 는 `list()` 호출과 `addRandomSuffix` 누락을 곧바로 실패로 만든다.
